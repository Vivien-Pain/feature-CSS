5. La validation intelligente (`:user-invalid`)

Date d'introduction : Fin 2023

Explication

Avant, utiliser la pseudo-classe :invalid posait un gros problème d'UX : les champs obligatoires apparaissaient en rouge dès le chargement de la page, agressant l'utilisateur avant même qu'il n'ait commencé à taper. La pseudo-classe :user-invalid résout cela en appliquant les styles d'erreur uniquement après que l'utilisateur a interagi avec le champ (par exemple, s'il tape une mauvaise adresse e-mail puis clique en dehors du champ).

Démo Live

Veuillez entrer une adresse e-mail valide.
Le nom d'utilisateur doit contenir au moins 5 caractères.

Essayez de cliquer dans un champ, de taper quelque chose d'invalide, puis de cliquer ailleurs. Remarquez que les champs ne sont pas rouges au chargement initial !

Code CSS

.form-control:user-invalid {
  border-color: #ef4444;
  background-color: #fef2f2;
}

.form-control:user-valid {
  border-color: #22c55e;
  background-color: #f0fdf4;
}

.form-control:user-invalid ~ .error-message {
  display: block;
}

Compatibilité et Fallback

Fallback : Sur les anciens navigateurs, la pseudo-classe sera simplement ignorée. Pour offrir une expérience similaire sans JavaScript, on peut utiliser un hack combinant :invalid et :not(:placeholder-shown) (qui cible un champ invalide uniquement si son placeholder n'est plus affiché), bien que ce soit moins précis que :user-invalid.
